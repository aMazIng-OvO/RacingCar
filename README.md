# Racing Car C-model

> **作者：aMaz1ng**
> 本项目基于 **浙江工商大学 哈夫克自动智能车项目** 进行二次开发（非官方分支，仅供学习与竞赛参考）。
> 底层驱动来自 [逐飞科技 STC32G144K 开源库](https://seekfree.taobao.com/)（GPL-3.0）。

---

## 1. 项目简介

面向 **全国大学生智能汽车竞赛（摄像头组 / 竞速组）** 的 STC32G144K246 平台完整竞速程序。

| 项目 | 配置 |
|---|---|
| 主控 | STC32G144K246，C251 内核，Keil MDK FOR C251，主频 96 MHz |
| 传感器 | 逐飞总钻风 MT9V03X 灰度摄像头，188 × 120，DMA + FIFO 采集 |
| 执行 | 舵机（PWME_CH3P_PA4）+ 双直流电机（PWMB 驱动）+ 双路正交编码器 |
| 人机 | 三个独立按键 + 双拨码开关 + 核心板蓝色状态灯 + USB CDC 调试串口 |
| 显示 | IPS200 已从硬件上移除，工程内不再有任何 `ips200_*` 调用 |

控制链路：**灰度图爬边线 → 透视去畸变 → 双侧融合中线 → 纯跟踪（Pure Pursuit）解算转向角 → 按曲率限速 → 双电机增量式 PID**。

当前编译结果（Keil C251 V5.60，目标 `stc32g144k246`）：

```
0 Error(s), 1 Warning(s)        仅逐飞库 zf_device_mt9v03x.c(138) C183
data=102.5  edata+hdata=8192  xdata=51380  const=48722  code=78525
```

`xdata` 余量约 13.8 KB。

## 5. 中断与并发

STC32G144K 没有 RTOS，实际是「主循环 + 抢占式中断」两级并发。

### 5.1 C251 只支持 0~31 号中断

芯片的扩展中断（`P0~PB`、`DMA UART`、`DMA_LCM`、`TM5~TM18`）真实向量号范围是 37~126，本工程实现了其中 37~99 区间的 26 个。C251 的 `interrupt N` 属性无法使用大于 31 的编号（`ERROR C168`），因此：

- `isr.c` 只放向量号 ≤ 31 的基础中断，由编译器自动生成向量表；
- `isr_extended_0.c` / `isr_extended_1.c` 在文件头加 `#pragma noiv`，函数用 0~31 的局部编号声明；
- `isr_extended_vectors.A51` 在真实向量地址（`CSEG AT 012BH` … `031BH`）放 `EJMP` 跳转。

改动中断逻辑时，扩展中断的处理函数写在 `isr_extended_*.c` 里，真实入口由 A51 决定。其余向量没有默认陷阱，**禁止使能未实现的扩展中断**。

### 5.2 三个上下文的分工

| 上下文 | 周期 | 职责 |
|---|---|---|
| 主循环 | 每帧 | 图像处理、元素决策、舵机与目标速度计算、按键扫描、调试输出 |
| TIM1（优先级 3） | 5 ms | 编码器读数、异常检测、出界消抖、速度环 PID、PWM 输出、毫秒节拍 |
| DMA_LCM（优先级 1） | 每帧 | 整帧搬运到快照缓冲 |
| INT1 / VSYNC（优先级 3） | 每帧 | 摄像头帧同步 |

### 5.3 控制量的所有权

| 共享量 | 写入者 | 读取者 | 保护方式 |
|---|---|---|---|
| `desiredSpeed` | 主循环（`setSpeedCommand()`） | 控制中断 | 写入过程关中断，控制中断每拍取一次副本 |
| `setSpeed` | 控制中断 | 控制中断内 | 单写者，无需保护 |
| `outOfTrack` | 主循环 | 控制中断 | 8 位，单字节明确 |
| `odometer` | 控制中断 | 主循环 | 读取前关中断取快照 |
| `faultFlags` | 控制中断 | 主循环 | 16 位，主循环只在状态变化时读一次 |
| `LRoadCount` / `RRoadCount` | 主循环 | 主循环 | 出界判定已移出中断，不再跨上下文 |
| `msTick` | 控制中断 | 主循环 | 16 位无符号，所有计时都用差值 |

主循环提交目标速度一律走 `setSpeedCommand()`，它在关中断的状态下写入并夹到 `SPEED_LIMIT` 以内。控制中断读到的目标速度不会出现半新半旧的值，也不会超过速度上限。

### 5.4 图像双缓冲

```
摄像头 ──DMA──► mt9v03x_image（采集缓冲，库内固定地址）
                      │  DMA 完成中断（LCM_DMA，优先级 1）
                      │  mt9v03x_dma_handler() → mt9v03x_frame_snapshot()
                      │  16 位字搬 22.5 KB，搬完置 frameBusy
                      ▼
              mt9v03x_frame（稳定快照，所有算法只读这里）
                      │  主循环以 frameBusy 为门控
                      ▼
          loadRoad() → 元素状态机 → 控制量 → frameBusy = 0
```

- 算法层一律读 `mt9v03x_frame`，`mt9v03x_image` 是 DMA 正在写的缓冲。
- 搬运在 DMA 完成中断内完成，`frameBusy` 为 1 时中断直接跳过搬运，丢弃来不及处理的新帧。这是可预期的丢帧降级，不会出现半帧混入。
- 5 ms 控制中断的优先级提到 3、`LCM_DMA` 降到 1，控制中断可以抢占这次搬运。
- 按键扫描与 `raceTask()` 在帧门控之外，摄像头停帧时急停与收车判定依然生效。

## 6. 控制链路

### 6.1 感知

`loadRoad()` 每帧依次执行：

1. `getLStart()` / `getRStart()`：从行 116 向行 70 按 3 行步长扫描，二分找到第一处灰度跳变，作为爬线起点。行 `BODY_ROW`(80) 及以上用两侧窄列（左 3~48、右 140~186）绕开车身，行 70~79 用全宽搜索兜底。
2. `getLBorder()` / `getRBorder()`：八邻域爬线，步长 2 像素，沿边线走到远端。每 2 步按 5 × 5 窗口重算局部阈值。爬线点数超过 25 时用局部阈值修正全局阈值。
3. `getGodRoadLine()`：查 `reflection` 表把斜视坐标映射到俯视坐标。
4. `filterRoad()`：因果平滑 `(前一点 + 当前点 + 1) >> 1`。
5. `resampleRoad(dis = 3)`：按弧长等距重采样，得到约 40 个点。
6. `findCorner()`：在重采样点的前段按夹角余弦找拐点，命中后截断边界。
7. 中线生成：按 `ALONG` 选一侧边界，沿法向平移 `centerLineDistance` 得到中线，再做一次 `filterRoad()` 与 `resampleRoad(dis = 2)`。

`ALONG` 决定用哪条边界外推中线，在 `loadRoad()` 末尾由两侧点数投票决定。拐点落在前 15 个点时，偏移从 18 改为 9。

### 6.2 决策

主循环根据 `RUN_MODE` 分派：

| 状态 | 处理 |
|---|---|
| `FORWARD` | `alongLine(centerLine, centerLineCount, getAimPos())` |
| `CROSS` | `runCross()`，补线后打向十字中心 |
| `L_ROUND` / `R_ROUND` | `runLRound()` / `runRRound()`，5 阶段状态机 |

进入元素的判据在 `main.c`，用边界点数与特定重采样点的坐标，阈值见第 8 节。`RUN_MODE` 离开 `FORWARD` 超过 8 秒会强制复位回 `FORWARD`，避免状态机卡死。

### 6.3 执行

`alongLine()` 用纯跟踪解算转向角：

```
dx = MT9V03X_H - 目标点行号 + DEVICE_H      // 前向距离
dy = 94 - 目标点列号                         // 横向偏差
δ  = atan(2·L·dy / (dx² + dy²))             // 等效轴距 L = DEVICE_H
```

`atan2_int()` 返回的就是转角的角度索引（0~30）。`setServoDuty()` 把转角换算成舵机脉宽偏移，同时按 `√(R·c4)` 算出弯道目标速度：

```
duty 偏移 = δ × c1 / STEER_DUTY_DIV
R         = 20000 / tan(δ)
目标速度   = min(√(R·c4), c5) × (入弯减速系数)
```

5 ms 控制中断读编码器、跑左右轮速度环、输出 PWM。差速量按曲率分配，最多占目标速度的一半，单轮目标同样夹在 `SPEED_LIMIT` 以内。

### 6.4 赛道判定

`trackEvaluate()` 每帧在 `loadRoad()` 之后调用一次，判据取自参考实现的出界条件：

```c
/* 参考实现的出界条件：两侧边界全丢 */
(!LRoadCount && !RRoadCount)

/* 当前实现的赛道判定：取补集 */
(LRoadCount > 0) || (RRoadCount > 0)
```

| `LRoadCount` | `RRoadCount` | 参考出界 | 当前赛道判定 |
|---|---|---|---|
| 0 | 0 | 成立 | 不在赛道 |
| 0 | 非 0 | 不成立 | 在赛道 |
| 非 0 | 0 | 不成立 | 在赛道 |
| 非 0 | 非 0 | 不成立 | 在赛道 |

判定的输入就是 `loadRoad()` 产出的边界点数，不额外读像素，相同输入必得相同结论。判据连续 50 ms 一致才切换状态，避免单帧抖动让指示灯来回跳。

赛道状态用于串口输出的 `STA` 字段与调试观察，**不阻断发车**，与参考实现的行为一致。

## 8. 参数

### 8.1 速度与舵机（`Motor.h`）

| 参数 | 默认值 | 含义 |
|---|---|---|
| `SPEED_LIMIT` | 400 | 目标速度上限，唯一的速度天花板。换算 `v(m/s) = 400 × 200 / PULSE_PER_METER` |
| `MOTOR_DUTY_LIMIT` | 10000 | 速度环输出上限（占空比满量程） |
| `MOTOR_BRAKE_DUTY` | 1500 | 刹车段允许的最大反向占空比，用于电子制动 |
| `STEER_DUTY_LIMIT` | 395 | 舵机单边脉宽偏移上限，等于 197.5 µs |
| `STEER_DUTY_DIV` | 20 | `duty 偏移 = 转角 × c1 / 20` |
| `BORDER_IN_SPEED_RATIO` | 70 | 入弯时目标速度压到 70% |
| `DEVICE_H` | 18 | 纯跟踪等效轴距（像素） |
| 转向环 PID | 100 / 0 / 100 | 直通 + 阻尼，增益已经在 `currentDuty` 里体现 |
| 速度环 PID | 1000 / 50 / 0 | 输入单位是「脉冲 / 5 ms」 |

### 8.2 八档整定参数（`main.c` `speedSet[8][4]`）

每行依次是：舵机增益 `c1`、前瞻点序号 `c3`、侧向加速度上限 `c4`、直道限速 `c5`。

| 档 | c1 | c3 | c4 | c5 |
|---|---|---|---|---|
| 1 | 260 | 26 | 2400 | 400 |
| 2 | 200 | 22 | 2000 | 300 |
| 3 | 210 | 23 | 2000 | 320 |
| 4 | 220 | 23 | 2000 | 340 |
| 5 | 230 | 24 | 2000 | 360 |
| 6 | 240 | 24 | 2000 | 380 |
| 7 | 250 | 25 | 2000 | 400 |
| 8 | 260 | 25 | 2000 | 400 |

- `c1`：每 1 度图像角度对应的舵机 duty = `c1 / 20`。c1 = 260 时 13 duty/度，转角打满 30 度得到 390 duty。
- `c3`：前瞻点序号，中线重采样间距 2 像素，c3 = 24 即约 48 像素前瞻。`getAimPos()` 会在此基础上按当前速度每 40 个单位再加 1 个点，最多加 20 个点。
- `c4`：侧向加速度上限，`a = v² / R = c4`。`PULSE_PER_METER = 34600`、1 像素 ≈ 1 cm 时，c4 = 2000 约对应 6.7 m/s²。
- `c5`：直道目标速度，最终再由 `SPEED_LIMIT` 封顶。

拨码 SW1 / SW2 决定基址（0 / 2 / 4 / 6），每组取奇数档。

曲率限速的实测曲线（c4 = 2000、c5 = 400）：

| 转角 δ | 曲率半径 R | 目标速度 |
|---|---|---|
| 0° | ∞ | 400（c5 生效） |
| 10° | 113 | 400（c5 生效） |
| 15° | 74 | 384 |
| 20° | 54 | 328 |
| 25° | 42 | 289 |
| 30° | 34 | 260 |

### 8.4 赛道判定（`Track.c`）

| 参数 | 默认值 | 含义 |
|---|---|---|
| `TRACK_CONFIRM_MS` | 50 | 判据切换的消抖时间（毫秒） |
| `LED_FAST_MS` | 100 | 蓝灯正向快闪的翻转周期（毫秒） |

判据本身由参考实现的出界条件取补集得到，没有可调阈值，见 6.4 节。

### 8.5 元素判据（`main.c`）

| 参数 | 默认值 | 含义 |
|---|---|---|
| `ROUND_ROW` | 37 | 环岛判定用的重采样点序号 |
| `ROUND_NEAR_X` | 20 | 该点行号小于此值视为边界已收到车头附近 |
| `ROUND_FAR_MAX` | 11 | 对侧边界点数上限 |
| `CROSS_MAX` | 14 | 十字判定的两侧边界点数上限 |

这些阈值是对特定赛道量化出来的，换场地需要重新标定。

### 8.6 里程（`Stop.h`）

| 参数 | 默认值 | 含义 |
|---|---|---|
| `CALIB_REQUIRED` | 0 | 1 = 未标定一圈就拒绝发车；0 = 放行且不自动刹停 |
| `PULSE_PER_METER` | 1000 | 每米脉冲数，仅供参考，实际圈长以推车标定为准 |
| `LAP_DISTANCE_CM` | 1200 | 赛道一圈长度 |
| `STOP_OFFSET_CM` | 100 | 过起跑线后继续前进的停车点 |
| `BRAKE_DISTANCE_CM` | 200 | 提前开始刹车的距离 |

`CALIB_REQUIRED = 0` 时不标定也能发车，此时圈长被设成极大值，不会自动刹停，靠 B3 手动停车。

## 9. 操作

| 操作 | 功能 |
|---|---|
| 拨码 SW1 / SW2 | 上电自动选档，4 组组合各对应一组参数 |
| **B2 短按** | 发车（完赛或急停后也可重新发车），不设赛道门槛 |
| **B3 短按** | 紧急停车，任何状态都生效 |
| **B4 短按** | 停车状态下让舵机左右各摆 15°，用来确认舵机供电与信号 |
| **B4 长按 2 秒** | 待发车状态下把当前里程记为一圈。成功闪 2 下，失败闪 4 下 |

按键全部以控制中断维护的 `msTick` 计时：20 ms 消抖、B2 长按 1000 ms、B4 长按 2000 ms。按下时蓝灯亮 60 ms 作为确认反馈，这个反馈是非阻塞的，不会丢帧。

上电顺序：蓝灯闪 3 下 → 摄像头初始化（最多重试 3 秒，失败则蓝灯慢闪并停住）→ 舵机左右自检约 1.5 秒 → 显示待发车。

### 9.1 蓝色状态灯

| 蓝灯 | 含义 |
|---|---|
| 上电闪 3 下后灭 | 自检正常 |
| 快闪约 5 Hz | 编码器计数递增（车轮正向转动） |
| 常亮 | 编码器倒扣、编码器掉线、PID 异常或出界停车 |
| 灭 | 编码器无变化（静止） |
| 短亮 60 ms | 收到按键 |

判断编码器方向最快的办法：手推车向前，蓝灯应闪烁。若常亮，说明该轮计数方向是反的，对调编码器 A / B 两根线。

## 10. 调试输出（USB CDC）

屏幕已从硬件上移除，所有读数通过芯片内置 USB 送到电脑。把 USB 线接到主控板，用任意串口工具打开虚拟串口即可。

待发车状态每 250 ms 输出一行，跑车中每 1 秒输出一行：

```
ODO=123456 L=86 R=72 C=95 THR=151 MODE=114 AL=99 ERR=0 SPD=0 DS=0 DUTY=0
```

| 字段 | 含义 |
|---|---|
| `ODO` | 累计里程（编码器脉冲） |
| `L` / `R` | 左右边界点数 |
| `C` | 中线点数 |
| `THR` | 全局阈值 |
| `MODE` | `114` 循迹 / `514` 十字 / `810` 左环岛 / `1919` 右环岛 |
| `AL` | `88` 用左边界外推 / `99` 用右边界外推 |
| `STA` | `1` 在赛道上 / `0` 不在赛道（两侧边界点数都为 0） |
| `ERR` | 故障位（十进制，见第 12 节） |
| `SPD` | 实测速度（脉冲 / 5 ms） |
| `DS` | 目标速度（脉冲 / 5 ms） |
| `DUTY` | 当前舵机偏移量 |

串口没有连接时 `usb_cdc_write_buffer()` 会立即返回，不占运行时间。

## 11. 标定流程

### 11.1 视觉标定

装车后先看 `L` / `R` / `C` / `THR` 四个读数：

| 读数 | 合格范围 | 不合格时怎么处理 |
|---|---|---|
| `THR` | 140~160 | 读到 128 表示采样区没有明暗差，先调安装角度，不要动参数 |
| `L` / `R` | 60~90，两者相差小于 20 | 小于 20：视野被赛道占满（摄像头太低/太近），或 `EDGE_DIFF` 过大 |
| `C` | 60~100 | 为 0：两侧边界都没出来；远小于 L / R：被拐点提前截断 |
| `MODE` | 直道恒为 114 | 直道上跳成 514 / 810 / 1919：元素判据阈值过松 |

三个必须记住的现象：

1. `THR = 128` 是对比度不足的兜底值，出现它就说明画面不能用，不要试图用 `EDGE_DIFF` 去救。
2. 桌面裸板调试时把 `HIDE_ROW` 改成 119，否则第 90 行以下、第 48~140 列会被当成车身，近处的左右边界会落进遮挡区。
3. 只有一侧能看到赛道外沿时，算法会把赛道外沿当成内沿，中线被推到赛道外。这种情况只能调安装。
4. 画面里有部分车身时，车身暗块会被当成赛道边界。先把 `BODY_ROW` 调到车身出现的最上行，让这些行改用两侧窄列搜索；车身若已经盖住了两侧边界（伸到列 48 以左或 140 以右），只能调摄像头高度或俯角。

### 11.2 赛道状态排查

串口 `STA` 为 0 表示"不在赛道"，判据是两侧边界点数都为 0。看这个字段时同时看 `L` / `R`：

| `L` / `R` | `THR` | 结论与处理 |
|---|---|---|
| 都为 0 | 128 | 画面没有明暗差，摄像头对着一片纯色。调安装角度，让它同时看到赛道与底布 |
| 都为 0 | 正常 | 边线没爬出来，按 11.1 节检查 `EDGE_DIFF` / `EDGE_RATIO` 与 `BODY_ROW` |
| 一个为 0 | 任意 | 判在赛道。单侧失效说明该侧边界被遮挡或超出视野 |
| 都不为 0 | 任意 | 判在赛道 |

赛道状态只做指示，不阻断发车。边界点数真正的消费者是元素判据与出界保护：`L` 与 `R` 同时掉到 0 会在 15 ms 内触发出界停车。

### 11.3 里程标定

1. 上电，确认 `ODO` 在推车时递增。
2. 从起跑线推车走完一整圈，再前进到需要的停车点。
3. 长按 B4 两秒。闪 2 下表示成功，串口会打印 `CALIB OK lap=<脉冲> brake=<脉冲>`。
4. 需要精确的每米脉冲数时，推车走 1 米，用 `ODO` 的增量填回 `Stop.h` 的 `PULSE_PER_METER`。

### 11.4 速度标定

`setSpeed` 的单位是「脉冲 / 5 ms」，与米每秒的换算关系：

```
v(m/s) = setSpeed × 200 / PULSE_PER_METER
```

把 `PULSE_PER_METER` 标定准确之后，按目标车速反算 `c5` 与 `SPEED_LIMIT` 即可。

## 12. 异常检测

`faultFlags` 在 5 ms 控制中断里判定，屏幕移除后通过串口的 `ERR` 字段与蓝灯读取。

| 位 | 值 | 含义 | 判定依据 | 是否停车 |
|---|---|---|---|---|
| `FAULT_STOPPED` | 0x0001 | 因异常被强制停车 | 上述任一异常 | — |
| `FAULT_ENC_L_DOWN` | 0x0002 | 左编码器无反馈 | 有速度指令、占空比已超过 20%，该轮 300 ms 内计数为零 | 是 |
| `FAULT_ENC_R_DOWN` | 0x0004 | 右编码器无反馈 | 同上 | 是 |
| `FAULT_PID_SAT` | 0x0100 | PID 输出打满且速度不达标 | 输出 ≥ 96% 上限且实际速度不到目标一半，持续 1 秒 | 是 |
| `FAULT_PID_REV` | 0x0200 | 速度环正反馈 | 正向输出且编码器持续反向计数 500 ms | 是 |
| `FAULT_OUT` | 0x0400 | 出界保护触发 | 两侧边界全丢或 5 个采样点全暗，连续 3 拍 | 是 |

使用约定：

- 发车时调用 `faultReset()` 清零，停车时保留，便于赛后回看停车原因。
- 发车后有 2 秒宽限期，避开 PID 起转与齿轮间隙。
- `FAULT_OUT` 只在出界分支置位，与"正常完赛停车"区分开。
- 检测逻辑只读控制量，唯一的写操作是判定为致命故障时置 `stop`。

## 13. 已知限制

1. **去畸变查找表不可现场调整**：`reflection[120][188][2]` 是离线标定产物，与参考实现 `version1.3` 同一份数据，摄像头位置或分辨率变化后必须重新生成。
2. **整帧拷贝在 DMA 完成中断内**：每帧 `memcpy` 22.5 KB，靠中断优先级抢占保证控制周期。C251 的高优先级中断能否抢占正在执行的 ISR 需要在实机上用 IO 翻转确认。彻底方案是 DMA 双缓冲，需要第二块 22.5 KB 缓冲，当前 XDATA 余量 13.8 KB 不足。
3. **元素判据与镜头安装强绑定**：`ROUND_ROW` / `ROUND_NEAR_X` / `ROUND_FAR_MAX` / `CROSS_MAX` 都以像素点数为单位，换赛道或换安装高度需要重新标定。
4. **`centerLineDistance = 18` 是假设值**：中线由单侧边界沿法向平移这个距离得到，摄像头装偏或赛道宽度与假设不符时整条中线会平移。
5. **摄像头 DMA 是预编译库**：`zf_device_mt9v03x_dma.LIB` 无源码，采集相关的行为无法从源码核实。
6. **逐飞库内的既有缺陷**：`zf_driver_encoder.c` 的正交编码器清零语句被注释、`TIM6/8/10_ENCODER` 清零恢复写成 `|= (1<<3)`；`zf_common_interrupt.c` 的 `IP/IPH` 分支用 `|=` 只能调高不能调低、`P8~PB` 分支移位溢出。已核对 Gitee 上游 `master`（V3.2.5，2026-06-27），与本地逐字一致，属于上游现存问题。本工程只用 PWMA / PWMC 正交编码器，且库内 `interrupt_set_priority(INT1_IRQn, 3)` 走置位方向，不受影响；`main.c` 新增的 `TIMER1_IRQn` 走 `IP/IPH` 置位方向、`LCM_DMA_IRQn` 走 `DMA_LCM_CFG` 的先清后置分支，同样不受影响。
